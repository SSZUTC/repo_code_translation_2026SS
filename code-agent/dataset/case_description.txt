### 一、漏洞是什么
Django 在 global_settings.py 里有一个安全设置：

SECURE_REFERRER_POLICY 控制浏览器返回的 Referrer-Policy HTTP 响应头。设置为 None 时，Django 完全不输出这个头，浏览器就会用自己的默认策略发送 Referer 请求头。
 典型攻击链
这在 OWASP 里属于**"敏感信息通过 Referer 泄漏"**，对应 CWE-200（Exposure of Sensitive Information to an Unauthorized Actor）。

### 二、为什么它是"真正的网络安全缺陷"
特征 是否符合 说明 默认行为造成的风险 ✅ None 意味着默认没有保护 可被远程利用 ✅ 攻击者只需在页面中放一个外链 / 资源引用 造成信息泄漏 ✅ 用户浏览路径、URL 参数、会话标识都可能被接收方读到 真实被用于攻击 ✅ Referer 泄漏是 CSRF token 窃取、用户追踪、账号枚举的常用手段 有标准修复方式 ✅ 浏览器已支持 Referrer-Policy: same-origin 等策略，无需改业务逻辑

官方 ticket 上维护者原话：
 "I think this fits our secure by default philosophy."
即：这是一个 安全默认值缺失 的真实安全缺陷，而非"顺手修一下"的最佳实践。

### 三、问题代码（需要分析的地方）
问题文件就是 Django 的全局默认设置 django/conf/global_settings.py 。相关的一段大概长这样（在 base_commit 7fa1a93c 状态下）：

SECURE_REFERRER_POLICY 被 SecurityMiddleware 消费，后者根据它的值决定在每个响应里写什么 Referrer-Policy 。设置为 None 时， 整个响应头都不写 。

### 四、修复补丁（参考正确答案）
整个修复只有 1 行代码 的改动：

- same-origin 的含义： 只有同源请求 （同一协议、域名、端口）才会在请求头里带完整的 Referer ；跨站请求则完全不带 Referer。
- 这是目前业界最主流的"安全默认值"。

## 题目 2：django__django-14376（第 153 条，三方包版本类）
定位：MySQL client 已弃用参数 · 难度 <15 min · version 4.0

### 题目内容
- repo ： django/django
- base_commit ： d06c5b358149c02a62da8a5469264d05f29ac659
- problem_statement 大意：
  - Django 的 MySQL 后端在调用 mysqlclient.connect(...) 时用的是旧参数名 db= 和 passwd=
  - 上游三方包 mysqlclient 已在新版本中 弃用 这两个参数，并推出 database= 和 password= 作为替换（详见上游 commit fa2535 ）
  - mysqlclient 1.3.8 之后才支持新参数，Django 2.2/3.1/3.2 的最低依赖版本都已经 >= 1.3.8，所以可以安全全面替换
### 修复补丁（2 个文件）
django/db/backends/mysql/base.py （真正的连接参数）：

django/db/backends/mysql/client.py （ dbshell 命令行工具）：

- 把 db 改成 database ，同时为了向后兼容， OPTIONS.get('database', OPTIONS.get('db', ...)) 先尝试新 key，再回退旧 key
- password 同理
### 对应测试
- tests/dbshell/test_mysql.py ：同时测试新 key（ database / password ）和旧 key（ db / passwd ）在 OPTIONS 中都能正确传递给命令行
- 新测试 test_options_non_deprecated_keys_preferred 专门校验：当同时提供新 key 时，优先使用新参数
### 为什么它是"三方包版本"类 这是一个标准的 跟上游依赖走 的适配任务：

- 没有逻辑 bug ——代码工作得很好，只是调用了三方包 即将被移除 的 API
- 原因在外部 ——mysqlclient 作为三方库升级了自己的接口约定
- 修复方式 ——跟随上游升级调用点，确保与新版 mysqlclient 兼容，避免未来该参数被移除后炸掉
- 这种"三方包弃用参数 → 调用方升级"是你能拿到的最典型版本兼容题
